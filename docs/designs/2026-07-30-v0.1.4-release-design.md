# v0.1.4 Release Design

## Release position

v0.1.4 is a substantial feature release on the existing v0.1 line. It is not
the v0.2 milestone: Little Alphaxiv remains under active iteration, and the
release should avoid implying that the current interaction model or feature set
is complete. The version collects the work merged after v0.1.3 into a coherent,
installable checkpoint for users who want the latest reading and chat workflow.

The release is organized around four user-facing themes: grounded PDF reading,
conversation branching, transparent agent activity, and provider/rendering
compatibility. Small visual fixes and race-condition fixes are grouped beneath
those themes instead of presented as equal-weight headline features.

## Documentation and delivery

The repository will carry three documentation layers. `README.md` and
`README.zh-CN.md` describe the current product capabilities. `CHANGELOG.md`
records the complete v0.1.4 delta using Keep a Changelog categories. A dedicated
`docs/releases/v0.1.4.md` page serves as the GitHub Release body and includes
highlights, upgrade notes, known limitations, and contributor credit.

The frontend package metadata will be synchronized to `0.1.4`. The release
branch must pass the same frontend and backend gates as `main`, then merge by
pull request. Only the merged `main` commit is tagged `v0.1.4`; the GitHub
Release is created from that tag. A Linux portable artifact is attached only if
it can be built and smoke-tested from a suitable Linux environment. Docker and
source installation remain fully supported regardless of artifact availability.

## Verification and rollback

Documentation links and version references are checked locally. Frontend
typecheck, Vitest, build, and backend pytest run before the PR. GitHub CI must be
green before merge. After merge, the release tag and GitHub Release are verified
through the GitHub API. Because tagging and publishing are outward-facing, any
failure before publication leaves the release unpublished; after publication,
corrections use an amended release body or a follow-up patch rather than moving
the public tag.
